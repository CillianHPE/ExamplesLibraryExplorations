Widget

A widget is a container whose job is to report: one question, one answer, one place to go next. This page fixes the anatomy every widget shares, where each kind of control lives, how widgets behave in edit mode, and the states they must handle. The Widget catalogue lists the canonical types that use this anatomy.

Where it sits

Widgets do not introduce a new container. They inherit Container and Content header unchanged and add three reporting slots on top: a scope line, a legend, and a footer. Anything a widget can do, a plain container can do; a widget is the reporting specialisation.

Widget type Widget catalogue
The job the widget does and the viz it uses: stat, trend, distribution, status list, exception, ranked table…
Two density tiers, one anatomy. Standard widgets use the full container spec (24px padding, 19px title, 24px header gap). Wallboard tiles on T5 · NOC keep the same slot order at tighter spacing. Nothing on this page is unique to custom boards: the same widget can sit in a T1 overview column, a T4 detail rail, or a T5 grid.

What a widget is not. A page-body table (D1), a form, or a data explorer (D4) is not a widget even when it lives in a container. Widgets summarise and point; they never host the full working surface.
Anatomy

Six zones, top to bottom. Only the header and body are mandatory; each optional zone has a fixed position so widgets stay scannable side by side. Vertical rhythm inside the widget is 16px between zones, with the standard 24px under the header row.

1 · Header is the Content header unchanged: leading title, one 36×36 trailing slot. Widgets may add an ⓘ definition tooltip after the title and a one-line scope under it (period, population, or filter summary). The trailing slot holds exactly one thing: a drill arrow, a kebab, or a single action.
2 · Local controls change how the body is shown, not what period it covers: view toggles (table/heatmap), group-by, series toggles, metric tabs. Never a date range.
3 · Body is one content type: a single visualisation (mark plus furniture), a list, a table preview, or a map. A widget that needs two charts is two widgets.
4 · Legend is owned by the Visualisation spec and sits below the body by default. Compact widgets may lift it into the header trailing area as a value-bearing legend ("4xx 0 · 5xx 2").
5 · Footer is the drill link (left) and freshness or scope (right). If the header already uses the trailing arrow as the drill, the footer drops the link and keeps only freshness.
6 · Edit chrome (drag grip, remove, size) appears only in edit mode and is drawn over the header row; see below.
Control placement

Where a control lives is decided by what it changes. Controls that change the question (period, population) belong to the page or section; controls that change the presentation belong to the widget body; navigation belongs to the header trailing slot or the footer.

Edit mode

Editing is a page state, not a widget state. Entering it changes the page header actions and overlays chrome on every widget at once. Content dims so structure reads over data. Rules from T5 · Custom board apply: 4-column grid, 16px gaps, sizes 1×1 / 2×1 / 2×2, ghost "+ Add widget" slot always last.

Page-level. "Edit board" enters the mode; the header swaps to Reset layout · Cancel · Save. "+ Add widget" opens the catalogue drawer (grouped by domain, each entry a live mini preview with Add). Save is the page's one primary.
Widget-level. Drag grip ⠿ before the title; ✎ Edit and ✕ Remove replace the trailing slot; size chip and resize grip bottom-right. Duplicate lives in the kebab, not the toolbar. Nothing in the widget is interactive apart from the chrome.
Outside edit mode widgets show no chrome at all. AWS and Supabase keep a permanent drag grip; we do not, because the grip competes with the title on every visit for a task done rarely.

Loading is a skeleton in the shape of the final content, never a spinner. Empty and Invalid configuration end in a link because the viewer can act. Unavailable gives the reason and never offers a retry the viewer cannot influence. All clear is a real result, so it keeps the drill arrow. No data for period keeps the headline value (0) and replaces the chart with a dashed placeholder so the widget footprint does not collapse. Status colour appears only in the icon or pill, never in text.
