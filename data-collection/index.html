Data collection page archetypes

Five canonical patterns for pages that display collections of data: tables, grids, streams, charts and maps. Start from the user's job, not the component: each card states the job to be done, the defining characteristics, and when the pattern fits or fails. Click through for the full archetype with a lo-fi spec and a GreenLake-styled example.

1 · Filterable inventory table

View archetype →

"Find and manage these 1,847 things."

The workhorse for operating a known set of objects. Users arrive with a target in mind (a server, a subnet, a policy) or a slice to act on (everything failing, everything in one site). Rows are peers; the value is comparing attributes across them and acting in bulk. If your users manage rather than browse, this is the default answer.

Search + filter chipsSortable columnsBulk-select action barColumn controlsPagination

Use when

The collection is large and attribute-rich, users know roughly what they're looking for, and rows need comparing or bulk action.

Not when

Users are choosing one unfamiliar item by identity (use the card catalog) or the order of events matters more than attributes (use the event stream).

2 · Card grid catalog

View archetype →

"Browse and pick one."

For choosing, not managing. Each item leads with identity: icon, name, one-line description, so users can recognise the right option among unfamiliar ones. Categories with counts do the narrowing; nobody sorts a catalog by column. The outcome is a single selection that starts a flow (provision, install, subscribe).

Uniform tilesIcon + name + descriptionCategory pills with countsOne-click select

Use when

Items are distinct offerings users pick from occasionally, and recognition (branding, description) beats attribute comparison.

Not when

Users return daily to operate on many items at once, or need to scan values across the set: that's the inventory table.

3 · Faceted event stream

View archetype →

"What happened, and when?"

For investigating time-ordered records: logs, audit trails, alerts. Users start from a symptom and narrow down: a time window, a severity, a user, a resource. The volume histogram is both overview and zoom control; facets with counts show where the signal is before a single row is read.

Time-ordered rowsVolume histogram + brushFacet sidebar with countsQuery barExpandable rowsLive tail

Use when

Records are immutable and time-stamped, questions are forensic ("what happened around 3pm?"), and volume is high.

Not when

Users need current state rather than history (inventory table), or aggregates matter more than individual events (analytics explorer).

4 · Analytics explorer

View archetype →

"What's the trend? Where's the anomaly?"

Chart-first: the collection is aggregated before it's shown. A scoped query (metric, aggregation, group-by, filters, time range) drives everything on the page, and the headline chart and breakdown table stay in sync with it. Users form and test hypotheses; individual records only appear at the end of a drill-down.

Metric switcherHeadline chartGroup-by breakdownTime range controlSynced drill-down

Use when

The question is about patterns over time or across segments, and the honest answer is an aggregate, not a row.

Not when

Users need to find and act on specific items: aggregation hides exactly what they're looking for.

5 · Map / spatial view

View archetype →

"Where is the problem?"

For collections where location is the organising attribute: sites, regions, devices in the field. Map and list are one collection with shared filters and selection; pins encode severity and magnitude at a glance. The map is a lens for spotting geographic clusters, never the source of truth: everything on it must be reachable through the list too.

Map + synced listShared filters & selectionSeverity-coded pinsPopover to detail

Use when

"Where" is a question users genuinely ask, and geographic clustering carries meaning (outages by region, sites by health).

Not when

Location is just an attribute among many: a filterable column serves better than a map that adds navigation cost.
