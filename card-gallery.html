Report an exception

Viewer's question: "Is anything broken or unprotected, and how bad?"

Lead with the exception count in absolute units, never the healthy percentage: nobody acts on 98%. The healthy majority demotes to muted chart mass and a caption. Must pass the zero test: at 0 exceptions the same layout reads as calm reassurance.

Use whenRoutine monitoring of a mixed-severity environment. The viewer needs the count and a sense of scale ("7 of 128") in one glance.
Not whenThe viewer must choose what to fix first. The bar shows severity, not blast radius: use the severity split instead.

Show a trend

Viewer's question: "Which way is this heading, and how fast?"

Lead with the current total: the number is only meaningful as a trajectory. Sparkline per the canonical spec: 2px non-scaling blue line, gradient fill, fixed 12px endpoint dot, no text in the plot; values live in the axis row as "date · value". Dashed prior-period reference only when the comparison is the story, and it gets a legend.

Sparkline with prior-period reference. The full spec: comparison line dashed and legended, endpoint dot ties "Today" to the line.

Use whenThe comparison against a prior period is the story: "faster or slower than last quarter" matters more than the shape alone.
Not whenThe delta pill already states the comparison. Encoding it twice adds ink without information.

Explain an insight

Viewer's question: "What does this number mean, and why should I care?"

Five-part anatomy: title + scope → headline figure + delta pill → decoder line (plain-language meaning) → evidence → takeaway ending in an action or reassurance. Use real units over ratios; make the arithmetic visible; deltas quantified in the headline's own unit.

Insight card. The arithmetic is visible (14.3 written, 3.4 stored, 10.9 saved); the takeaway converts it to money. No ratios, no jargon.

Use whenThe metric is derived or abstract (efficiency, scores, ratios) and the viewer can't be assumed to know what it means.
Not whenThe number is self-explanatory ("3.4 PB used"). A decoder line under an obvious figure reads as filler.

Prompt a deadline

Viewer's question: "What runs out, when, and what happens if I miss it?"

Headline the count due; the pill carries the nearest concrete date, not a restated stat. The breakdown buckets by urgency window. The takeaway must state the consequence of missing the deadline, then the action and date.

Use whenItems expire on hard dates with real consequences: subscriptions, licences, certificates, warranties.
Not whenThe date is a soft target or forecast. Stating a consequence you can't stand behind erodes trust: use a trend or insight card instead.

Summarise a distribution

Viewer's question: "What is this made of, and does anything dominate?"

A posture job: proportion is the message, so donuts and full-width meters are appropriate here (unlike exception cards). Order segments largest-first unless a status order applies. Never render zero-count legend entries. If the viewer is meant to act on one slice, this is the wrong job: use an exception card.

Use whenProportion is the message and the viewer just needs posture: "what is this made of, does anything dominate."
Not whenThe viewer is meant to act on one slice. That's an exception job: lead with the count that needs attention instead.
