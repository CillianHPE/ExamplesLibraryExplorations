Widget catalogue

Fourteen canonical widget types in five families, each defined by the question it answers rather than the chart it draws. Every type uses the shared widget anatomy, maps to a source page (T1–T5, D1–D5), and states when it fits and when it does not. Pick the type from the viewer's question first; the visualisation follows.

W1 · Measure

Stat

Is this metric where it should be?

One number, its direction, and just enough shape to trust it. The most common widget on every product surveyed. The sparkline is optional; the delta is required.

Body

Big number with unit, delta pill vs prior period, 72px sparkline per the sparkline spec. Axis row "date · value".

Controls

Header trailing arrow drills to the T3 chart. No local controls. Scope line states period and population.

Sizes

1×12×12×2 Wider stats become W3.

Source

T3 analytics metric or T4 detail attribute; on T1 the same figure appears in the KPI strip.

Use when

One figure carries the decision and has a meaningful prior period.

Not when

The number has no comparison (use W2 caption instead), or the trend shape is the point (W3).

W2 · Measure

Stat cluster

What are the headline figures?

Two to four related stats that only make sense together (current, forecast, previous, remaining). The widget form of the T1 KPI strip, for boards where the strip is not available.

Body

2×2 grid of label / value / caption. Captions carry the comparison in words; no sparklines.

Controls

Kebab in header; drill link in footer left, freshness right.

Sizes

1×12×12×2

Source

T1 KPI strip or T3 report header.

Use when

Figures share a unit and a story; the viewer reads them as one sentence.

Not when

Stats are unrelated (four W1s), or one dominates (W1 with the rest as caption).

W3 · Measure

Trend

How is this changing over time?

The shape of the line carries the message, so it gets the whole body. One series, or one series against its prior period; the axis row stands in for a y-axis and the endpoint value stands in for a tooltip.

Body

Line or area time series, blue current, dashed prior period. Up to three series before it becomes a D4 explorer.

Controls

Legend below, entries toggle series. Optional metric tabs in the local-controls zone when one chart serves several measures. Period comes from the page.

Sizes

1×12×12×2

Source

T3 analytics page; D4 explorer for the full series set.

Use when

Shape, slope, or seasonality matters more than the current value.

Not when

Only the latest figure matters (W1), or categories rather than time are on the x-axis (W4).

W4 · Compose

Comparison

Which is biggest, and by how much?

Categories side by side. Horizontal ranked bars are the default because labels stay readable; grouped or stacked columns only when a second dimension (period, status) is essential.

Body

Ranked horizontal bars, value right-aligned, ≤6 rows. Single colour unless status is the second dimension.

Controls

Optional Group by or Sort select in the local-controls zone. Footer drill names the remainder ("View all 11 services").

Sizes

1×12×12×2

Source

T3 analytics breakdown; D1 inventory sorted by the measure.

Use when

The viewer ranks or picks between named categories.

Not when

Categories sum to a meaningful whole (W5), or rows need more than one figure (W9).

W5 · Compose

Distribution

What is it made of?

Parts of a whole where the whole is the headline. Donut with the total in the centre for ≤5 segments; a stack bar with legend rows when the widget is short or the segments are ordered.

Body

Donut + legend rows with counts (never percentages alone), or .stack-bar + .legend-row. Status order critical → warning → ok → unknown; zero-count segments omitted.

Controls

Legend rows are the drill: each filters the D1 table by segment. Header arrow opens the unfiltered table.

Sizes

1×12×12×2

Source

D1 inventory table filtered by the segment attribute.

Use when

Segments are exhaustive and sum to a total the viewer recognises.

Not when

More than five segments (W4 ranked), or segments do not sum (W4).

W6 · Compose

Capacity

How close to the limit?

Used against a fixed total with a threshold the viewer cares about: storage, licence seats, budget, credits. A linear meter beats a gauge: it reads at a glance, aligns with neighbours, and shows the threshold as a tick.

Body

Percentage headline, verdict pill, "used of total" line, .meter with threshold tick. Bar colour follows the verdict (ok / warn / crit); text never does.

Controls

Footer left is the remedial action link ("Plan expansion", "Adjust budget"); footer right the projection ("Full in ~41 days").

Sizes

1×12×12×2

Source

T4 detail of the constrained object; budget page for spend.

Use when

There is a hard or agreed ceiling and a threshold that triggers action.

Not when

There is no ceiling (W1), or several objects need comparing (W7 or W9 with bar-in-cell).

W7 · Monitor

Status list

What is up and what is down?

A short roll of named things each with one state. Sorted by severity, so when everything is fine the eye can stop at the first row. Uptime bars add 30 days of history without a chart; hover a segment for the day and duration.

Body

≤6 rows: status dot · name · optional uptime bar · state word. Uptime bar = one segment per whole time unit (30 for 30 days, 24 for 24 hours), newest right; segment colour is the worst state in that unit, never a percentage. Scope line names the unit ("Last 30 days · daily"). Status order critical → warning → ok → unknown. Overflow becomes "+ 4 more" in the footer.

Controls

Header arrow to the full status page or D1 filtered to these objects. Rows are links to T4.

Sizes

1×12×12×2

Source

D1 inventory with status column; T4 object detail per row.

Use when

The viewer watches a fixed, nameable set of things.

Not when

Only the count matters (W8), or the set is large and anonymous (W5 distribution).

W8 · Monitor

Exception

What needs me now?

Count of things wrong, split by severity, with the worst few named. The whole widget is a door into the T2 triage queue. When nothing is wrong it shows the all-clear state and stays on the board.

Body

Big count, severity pills in status order (zero counts omitted), then ≤3 top items with age. Canonical form in Report an exception.

Controls

Header arrow to T2. Pills filter T2 by severity. No kebab: nothing here is secondary.

Sizes

1×12×12×2 1×1 drops the item list.

Source

T2 triage / work queue.

Use when

Items have severity and an owner who must act.

Not when

Items are informational (W10), or the set is fixed and mostly healthy (W7).

W9 · Monitor

Ranked table

Who are the top or bottom N?

A preview of the D1 table, pre-sorted by the measure that matters, cut at the rows that fit. The widget does not scroll; the footer states how much more there is and links to it.

Body

Table with ≤3 columns and ≤6 rows; first column is the object link, last is the ranking measure, optionally as bar-in-cell. Header row uses the table spec, at 12.5px.

Controls

Optional Sort select in local controls. Footer: "View all N" left, "1–4 of 42" right. Kebab for Download data.

Sizes

1×12×12×2 2×1 = 4 rows, 2×2 = 6 rows.

Source

D1 inventory table with the same sort applied.

Use when

Rows need two or three attributes to be recognisable and comparable.

Not when

One figure per row is enough (W4), or the viewer needs to filter or act in bulk (send them to D1).

W10 · Explain

Activity

What happened recently?

Newest first, relative time, one line per event. It provides context rather than alerting, and because nothing here demands action it uses no status colour or pills.

Body

≤6 rows: relative time · bold subject · plain event. Absolute time on hover. No icons unless the event type matters.

Controls

Header arrow to D3. No local filters; if the viewer needs to filter, they need D3.

Sizes

1×12×12×2 Extra height adds rows; extra width adds nothing.

Source

D3 faceted event stream.

Use when

Order in time is the organising idea and events are heterogeneous.

Not when

Events need triage (W8), or they are homogeneous counts over time (W3).

W11 · Explain

Heatmap

Where or when does it concentrate?

Two dimensions and an intensity: hour × weekday, impact × likelihood, region × service, or a map. Viewers read the overall pattern first and individual cells on hover.

Body

Cell grid with single-hue ramp (blue), row and column labels, gradient legend below. Risk matrices use the status ramp instead. Maps use D5 conventions.

Controls

Optional Table / Heatmap segmented toggle in local controls. Kebab: Download data. Cells drill to D4 or D5 with both dimensions applied.

Sizes

1×12×12×2 Smaller sizes lose the row and column labels.

Source

D4 analytics explorer; D5 map for spatial.

Use when

Two categorical or time dimensions and the viewer looks for hot spots.

Not when

One dimension would do (W3 or W4), or exact values matter (W9).

W12 · Explain

Insight

Why is this happening, and what should I do?

A finding in a sentence, the evidence in another, and one thing to do about it. Generated or curated, it is the only widget where prose leads. It is dismissible because insights go stale.

Body

Icon · headline (the finding, with the number in it) · evidence line · up to two actions, secondary and default. Canonical form in Explain an insight.

Controls

Kebab: Copy link, Dismiss, Hide this kind. Action buttons in the body, never primary.

Sizes

1×12×12×2

Source

The T3 chart or T4 object the evidence came from.

Use when

The system knows something the viewer would not see from the raw widgets.

Not when

The message is a threshold breach (W8 or W6), or a permanent explanation (put it in the ⓘ tooltip).

W13 · Act

Goal

Am I on track, and how long is left?

Progress against a target with a date. Combines a ring or countdown with the four numbers that make "on track" checkable: done of total, time left, required pace, current pace.

Body

Progress ring with percentage, or big countdown ("73 days") when the date matters more than the count. 2×2 stat grid alongside. Deadline form in Prompt a deadline.

Controls

Header arrow to the object or programme (T4). Footer optional: the remedial link when behind pace.

Sizes

1×12×12×2

Source

T4 detail (subscription, project, migration wave).

Use when

There is an agreed target and a date.

Not when

The limit is a ceiling to stay under (W6), or there is no date (W1).

W14 · Act

Quick actions

Where do I go next?

The one non-reporting widget. A short list of destinations or starts, for boards where the page has no secondary rail to hold them. Every product surveyed has one, usually as an uncontained link list in a rail.

Body

≤6 link rows, verb-first labels, trailing arrow. No icons, no descriptions.

Controls

No header or footer controls; each row is itself the action. The header trailing slot stays empty.

Sizes

1×12×12×2

Source

Any page; the destination list is per persona.

Use when

A T5 board replaces the T1 secondary rail and needs its entry points back.

Not when

The page already has a rail or a primary action for the task; a widget never carries .btn.primary.

How this fits the container architecture

Page → Section → Container → Widget → Widget type. The catalogue only adds the last layer.

Containers say what earns grey and how padding works. Content header says what a title row is. Widget adds the scope line, legend, footer, edit chrome, and states that every reporting container needs. Widget types say which body goes inside for which question. The card gallery remains the place where presentation variants and states of a type are worked through in detail; W1, W3, W5, W8, W12 and W13 link to their gallery job. A T1 overview is a fixed arrangement of these types; a T5 board is a viewer-chosen one; a T4 detail rail borrows W1, W6 and W10.
