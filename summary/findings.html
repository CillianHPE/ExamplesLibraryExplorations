S2 · Findings list

Rows with a marker and one action each, for working through. The marker (a severity pill, a countdown pill, or a tick) and the sort order are the whole difference between the three variants. This is the default shape for an overview page: it has the same anatomy as every other widget and can be read or acted on.

Shared anatomy

Every summary section, whatever its job, is built from the same four parts. Build these once in Figma as the base component; the variants below only change what goes in the item slot.

S2a · Triage list

Job: "Show me what is wrong, worst first." Everything that currently fails a rule, ranked by severity, each with the one place to go and fix it.

Use when
Health, security and compliance overviews. Operators who open the page to find out what to do next.
Not when
There is nothing wrong most of the time; an empty triage list is a sad widget. Use S1a and let the strip show green.
  1. Header: "Needs attention" + count pill, scope "Checked N minutes ago · population"
  2. Right action: "Show dismissed (n)" when anything has been dismissed
  3. Row: severity pill · lead with count · reason · link · kebab (warning rows only)
  • Sort: critical, then warning; within a level, larger count first
  • Lead names the finding and its size: "42 devices silent for more than 7 days"
  • Reason gives where or why, not a restatement
  • Pill copy is the level word only: Critical, Warning. Never "High" or "Sev 1"
  • Max 5 rows visible; the sixth onward goes behind "View all (n)" in the header
  • Default: 2 to 5 rows
  • Single row: still a list, no special layout
  • Empty: section is removed; the stat strip shows the all-clear
  • Overflow: 5 rows + "View all (n)"
  • Per row from the kebab: Dismiss, Snooze 7 days. Not on critical rows
  • Dismissed rows are recoverable from "Show dismissed (n)" in the header
  • A dismissed row returns if its severity rises
  • Pill column 84
  • Variants: row × severity (critical / warning) × overflow (none / kebab)
  • Component props: count, checked-at, rows (1–5), dismissed count

Job: "What runs out, and when?" Things with a date on them, sorted by the date, so the reader sees how much runway there is.

Use when
Subscriptions, licences, certificates, trials, contracts. Pages where time, not severity, is the ranking.
Not when
The items have no date, or they all share one. If nothing is inside 90 days, show the count and nothing else.
  1. Header: "Coming up" + count pill, scope "Next 90 days · population"
  2. Right action: "View all subscriptions" (or the relevant object)
  3. Row: countdown pill · lead ("X expires on Y") · reason (what it covers, auto-renew state) · link · kebab
  • Sort by date, soonest first
  • Pill copy is the countdown: "In 6 days", "In 23 days". Tint red inside 7 days, amber inside 30, grey beyond
  • Lead names the object and the owner: "Compute Ops Management expires on Alpha Bank"
  • Reason carries the consequence or the auto-renew state
  • Rows that need no action still appear (so the reader can trust the list is complete) but have no link
  • Default: 3 to 5 rows inside the window
  • Empty: a single line "Nothing due in the next 90 days", no rows, no count
  • Past due: pill reads "Overdue", red, sorted to the top
  • Per row from the kebab: Hide until 7 days before
  • Not on rows inside 7 days
  • Rows leave when renewed or when the date passes and the item is resolved
  • Pill column 96 (countdown is wider than a level word)
  • Variants: pill × window (week / month / beyond / overdue)
  • Component props: window label, rows (0–5) with date, object, owner, consequence, link?

Job: "What is left to finish?" A fixed set of steps toward a known end state, with the finished ones ticked so the count climbs.

Use when
Onboarding, rollouts, migrations. Any time the list is the same for everyone and ends. Finished items stay visible until the whole thing is done.
Not when
The set is open-ended or keeps refilling; that is a triage list. Also not for optional improvements, which are S3b.
  1. Header: "Set up this account" + "3 of 5" pill, scope "Done when …" (the end state in one line)
  2. Right action: "Skip setup"
  3. Row: tick circle (done or empty) · lead · reason (evidence: "15 created") · link on open rows and on done rows that can be revisited
  • Fixed order; the same steps for every account
  • Done rows stay, struck through in soft ink, with their evidence
  • Open rows show the gap as the reason: "9 of 15 workspaces have none"
  • The count in the title is done-of-total, never a percentage
  • Lead is the step as an imperative: "Assign subscriptions"
  • Default: all steps visible, done first
  • All done: section removes itself on the next visit (optionally a one-time "Setup complete" line)
  • Skipped: section hidden; reachable from account settings
  • No per-row dismiss; steps are not optional
  • "Skip setup" hides the whole section, persists per account
  • Tick 20 r10, --ok-bg with ✓ 12/700; empty 1.5px --line border
  • Done lead: 14/500 --gl-ink-soft, line-through in --line
  • Component props: done, total, end-state text, rows with state (done / open)
